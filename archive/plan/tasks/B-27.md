# B-27. Re-record the cassettes against a live model

**Phase:** B | **Depends on:** B-26 | **Read:** `docs/CONTRACTS.md` and `history/plan/components/13-llm-client.md`

Load **only** those two documents plus this file. Do not read the rest of `history/plan/`.

---

## Build

**OPTIONAL. Do this only if B-26 is green and everything else is done.** Nothing depends on it.

The committed cassettes carry `origin: AUTHORED_FIXTURE`. They were written by hand so the suite and
the demo run with no endpoint. This task replaces them with real recordings.

```bash
uv run wha llm record --scenario illness-onset
uv run wha llm record --scenario red-flag
uv run wha llm record --scenario injection-poisoned
uv run wha llm record --scenario stress-mimic
```

Each writes `origin: RECORDED` with the real `model_id` and real token usage. Then re-run the
scenario suite.

**If a recorded response changes a scenario's disposition, that is a finding, not a failure.** It
means the authored fixture and a real model disagree about something the pipeline is sensitive to.
**Record it in `plan/BLOCKERS.md` and keep the authored cassette.** Do not adjust the fixture's
`expect` block to accommodate the recording.

```bash

```

Plus: `uv run pytest` green **in full**, `uv run ruff check src tests` clean, no test weakened, no
contract changed.

## Do not

- **Do not run this before everything else is done.** It costs real API calls and it is optional.
- Do not delete an authored cassette. Recording writes alongside it; the loader prefers `RECORDED`.
- **Do not change a scenario's `expect` block** because a real model produced something different.
  That is the finding.
